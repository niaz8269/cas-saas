# ADR-0002 — React 19 (supersedes the React 18.3 pin in ADR-0001)

**Status:** Accepted (approved by product owner, 2026-07-17)

## Context

During M0.5 (login screen), forms silently broke: shadcn/ui's current registry generates
components in **React 19 style** — `ref` passed as a regular prop, no `forwardRef`. Under
React 18.3 the ref never reaches the DOM node, so react-hook-form cannot register inputs
(fields always read as empty). Console symptom: *"Function components cannot be given refs."*

## Options considered

1. **Upgrade to React 19** — stable since Dec 2024; TanStack Query 5, React Router 7,
   RHF 7, Testing Library 16 and Vite all fully support it. shadcn components work as
   generated, forever.
2. Stay on 18.3 and hand-convert every generated shadcn component to `forwardRef` —
   recurring manual rework on each `shadcn add`, permanent drift from upstream.

## Decision

**React 19** (`react`/`react-dom` `^19.1`, `@types` `^19.1`). Option 2's per-component
tax compounds across the entire build (M1–M9 add dozens of components).

## Consequences

- CLAUDE.md stack line updated: React 19 + TypeScript.
- New components must use React 19 idioms (`ref` as prop; no `forwardRef` in new code).
- No runtime code changes were required — the scaffold had no React-18-only patterns.
